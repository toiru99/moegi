현재 프로젝트 폴더를 MOEGI 게임으로 만들고, 사용자의 브리프대로 콘텐츠를 제작하라.

사용자 브리프: $ARGUMENTS
(브리프가 비어 있으면 먼저 어떤 게임을 만들고 싶은지 한국어로 물어라 — 장르·분위기·주인공 정도면 충분하다.)

## 절차

1. **진단**: `python "${CLAUDE_PLUGIN_ROOT}/scripts/doctor.py"` 실행. 실패하면 출력의 안내를 사용자에게 전하고 중단.
2. **스캐폴드**: `python "${CLAUDE_PLUGIN_ROOT}/scripts/scaffold.py" --dest "<프로젝트 절대경로>"` — 멱등이므로 이미 게임이면 그대로 통과.
3. **스토리 바이블**: 게임 루트에 `story.md`를 작성한다. 필수 섹션 — `## 시놉시스·톤`, `## 아트 스타일`(이미지 생성 시 모든 프롬프트에 붙일 공통 스타일 프롬프트), `## 캐릭터`(인물별 성격·말투·외형·**base 생성 프롬프트 원문**), `## 플롯 상태`, `## 제작 로그`(에셋별 생성 프롬프트). 생성하지 않은 에셋(스타터/사용자 제공)은 프롬프트 대신 **출처와 라이선스**를 기록한다. 이 파일이 나중에 `/moegi:continue`가 일관성을 지키는 근거다 — 에셋이 늘 때마다 갱신하라.
4. **제작**: vn-scene 스킬의 루프(작성→컴파일→렌더→시각검증)를 따르라. 핵심 규칙:
   - 모든 moegi MCP 툴 호출에서 `game_root`와 파일 경로는 **프로젝트 절대경로**를 쓴다 — 상대경로의 기준은 사용자 프로젝트가 아니라 엔진 홈이라, 엉뚱한 곳에 파일이 생긴다.
   - 에셋은 **동봉 스타터 에셋 재사용을 먼저 검토**하고, 부족하고 **브리프가 AI 생성을 금지하지 않을 때만** 생성한다. 생성할 경우: 먼저 `estimate_asset_cost`로 비용을 확인해 사용자에게 알리고, 캐릭터는 `generate_character_set`(같은 얼굴 보장), 배경/CG는 `generate_image`, BGM은 `generate_bgm` — 프롬프트에는 story.md의 아트 스타일 프롬프트를 붙인다.
   - 장면 전환 시 `@hideall` — 스탠딩은 지우기 전까지 무대에 남는다.
5. **검증**: `render_scene`으로 대표 장면들을 찍어 **Read로 직접 보고**, 분기가 있으면 `playtest`로 완주 확인(최종 state의 `label`이 기대 라벨인지 — `mode`가 `title`이면 진행 실패다). 시각 검증 없이 완료 보고 금지. 렌더가 갑자기 검게 나오면 엔진 로그의 `texture not found`와 `assets/` 실재부터 확인하라.
6. **마무리**: 만든 것 요약 + 실행 방법(doctor가 출력한 moegi 경로로 `moegi.exe <게임 절대경로>` — dev 소스 트리라면 `<엔진 홈>\moegi.cmd <게임 절대경로>`) + `/moegi:continue`로 이어 만들 수 있음을 안내.
