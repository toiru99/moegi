현재 프로젝트 폴더의 MOEGI 게임을 이어서 작업하라.

사용자 요청: $ARGUMENTS

## 절차

1. **컨텍스트 복원이 첫 단계다** — 코드를 만지기 전에 반드시 읽어라:
   - `story.md` (스토리 바이블: 톤, 아트 스타일 프롬프트, 캐릭터 시트, 플롯 상태, 제작 로그)
   - `characters.json`, `scenario/` 전체, `CREDITS.md`(있으면 — AI 생성 0건인 게임엔 없다)
   - `story.md`가 없으면(플러그인 이전에 만든 게임) 위 파일들과 렌더 확인으로 역공학해 **먼저 story.md를 만들어라** — 섹션 구성은 `/moegi:new`와 동일하게 5개(`## 시놉시스·톤` / `## 아트 스타일` / `## 캐릭터` / `## 플롯 상태` / `## 제작 로그`)로 고정한다. 그다음에 작업한다.
2. **일관성 규칙**:
   - 스토리: `## 플롯 상태`에서 이어 쓴다 — 말투·호칭·설정을 임의로 바꾸지 마라.
   - 사용자 요청이나 story.md가 AI 생성을 금지하면: 동봉·기존 에셋만 재사용하고, 부족하면 사용자에게 요청한다. 생성이 허용될 때만 아래를 적용 —
   - 새 배경/CG: story.md `## 아트 스타일`의 공통 프롬프트를 재사용한다.
   - 기존 캐릭터의 새 표정: `generate_character_set`에 같은 `name`과 story.md에 기록된 base 프롬프트로 요청 — base가 캐시에 있어 같은 얼굴로 표정만 추가된다.
   - 새 캐릭터: 기존 캐릭터들과 같은 스타일 프롬프트 접미사를 쓰고, base 프롬프트를 story.md에 기록한다.
3. **제작**: vn-scene 스킬의 루프를 따르되, `game_root`/경로는 항상 프로젝트 절대경로. 기존 라벨을 깨뜨리지 않게 `validate_project(path=<시나리오 절대경로>, game_root=<게임 절대경로>)`로 미도달 라벨/누락 에셋을 확인하라.
4. **검증**: vn-scene 스킬 4·5단계 그대로 — 렌더는 콜드 점프이므로 검증 라벨은 @bg 자급. playtest는 **새 분기뿐 아니라, 이번 변경으로 흘러드는 기존 루트 전부**를 완주시켜라(종착이 바뀐 기존 분기 포함).
5. **바이블 갱신**: 작업이 끝나면 story.md의 플롯 상태·제작 로그를 갱신한다 — 단순 append가 아니라, 이번 변경으로 **모순이 된 기존 서술은 고쳐라**. 다음 세션의 자신에게 남기는 인수인계다.
