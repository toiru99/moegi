---
name: vn-director
description: Plan and produce developed visual-novel chapters in VN Studio, including cast, scene writing and real image/audio tasks, even when a creator only asks to make a game.
---

Make the requested visual novel concrete in the existing VN Studio project. Apply this workflow automatically to new-game and chapter requests; the creator does not need to name this skill or request images separately. Keep ordinary explanations in the creator’s language.

Read the project and its current revision. For a new project use `vn_project create`, then `vn_director`. Preserve unrelated scenes, visual composition, audio and imported assets. Use the current entry scene as the first planned scene. System menus, save/load and playback controls belong to the installed game system; spend the chapter’s writing budget on the story.

Before drafting, save a production bible with `vn_director plan`. Record premise, tone, a small cast with distinct voices and desires, scene purpose, a concrete shared activity, relationship before/after, action/reaction beats, continuity notes and required media. Use the configured scene and beat defaults in the automatic director instructions, unless the user requests a shorter work, another pacing or a genre that calls for different development. A vague “make a game” is sufficient authorization to plan, write and prepare original media; choose a coherent premise and state it briefly instead of asking the user to specify every production task.

For an ordinary first chapter, develop five scenes with roughly 12–20 dialogue/narration beats each. Let characters do a modest everyday task together: sort books, prepare a club room, repair an umbrella, cook, or tidy a workspace. Show pauses, small failures, physical reactions and changed behaviour before naming a feeling. Early scenes establish voices and habits; later scenes earn a small change in trust. Do not compress meeting, confession and commitment into three abrupt scenes. An explicit request for a very short story overrides these defaults; record the corresponding smaller pacing targets.

`planJson` is an object with:

- `version:1`, `premise`, `tone`, `pacing:{minScenes,minBeats,maxBeats}`.
- `cast:[{id,name,voice,desire}]`.
- `scenes:[{id,title,purpose,sharedActivity,relationshipBefore,relationshipAfter,relationshipChange:"none"|"small"|"major",beats:string[],continuity:string[]}]`.
- `media:[{id,kind:"background"|"character"|"music"|"sound",name,sceneIds:string[],prompt?,scoreJson?,preset?,assetId?}]`.

The plan adds empty placeholders for missing scenes; these are outlines, not completed writing. Write each scene with `vn_director write_scene`, supplying `sceneJson:{id,lines:[{speaker,text}],choices?:[{text,target}],title?,visual?}`. Branch targets must already exist. Omitted choices and omitted visual roles retain saved values. Make choices express a plausible difference in action, then give each path a coherent continuation. Continue writing until the requested chapter is actually saved.

Model mutation results are compact receipts: `{id,revision,changedSceneIds,changedMediaIds,addedAssetIds,counts:{scenes,beats,assets,mediaTasks}}`. `prepare_media` also returns `status`, including real asset ids and pending, blocked or unassigned tasks. Continue with the returned top-level `revision`; do not read the entire project after every mutation. Use `read` for the full saved project when you need content you have not loaded or after a revision conflict. Receipts acknowledge saved changes; counts alone do not establish a finished game.

Plan location backgrounds, relevant cast portraits, a suitable original BGM score and meaningful effects without waiting for a separate media request. Reuse an existing suitable asset intentionally by setting its real `assetId`; never invent an asset id. Keep character appearance and style consistent in prompts across scenes. In `planJson`, a music task’s `scoreJson` accepts either a score object such as `{tempo:90,instrument:"piano",notes:[{midi:60,beat:0,duration:1,velocity:0.4}]}` or a JSON string containing that object. It is validated and saved as a string, which `vn_media compose` also accepts. Bounds are tempo 40–180, instrument piano/pad/bell, 1–512 notes with integer MIDI 36–96, beat 0–128, duration 0.0625–8, velocity 0.01–1, total duration at most 60 seconds. A score error names `production.media[index].scoreJson`; correct that score instead of repeatedly shortening and rewriting unrelated plan fields. Effects use `preset:"bell"|"rain"|"steps"` when appropriate.

Each scene supports at most three visible character placements. A portrait task’s `sceneIds` specifies scenes where that portrait must actually be placed, not every scene where its character is mentioned or speaks offstage. For scenes with a larger cast, split the staging into connected scenes at natural action beats, keeping at most three visible people in each. Preserve dialogue, choices and continuity when splitting. If a character remains offstage or a required portrait is not assigned, report that fact; creating the image alone does not satisfy a placement requirement.

Call `vn_director prepare_media` after saving the plan. Prefer the native `codex-images` provider when ready; it uses the signed-in Codex image capability. `vn_media status` reports actual availability, and `prepare_media` selects ready Codex images before other image providers. It also uses the real local score/effect tools, validates imported files and assigns compatible visual roles. Calls are bounded: repeat automatically using the returned revision while executable media tasks remain, without waiting for another user request. Existing occupied visual roles are preserved; resolve a reported unassigned asset deliberately with `write_scene`. Do not loop on blocked tasks. If no image provider is ready, retain the requirements and explain the reported connection or file-import option. Continue useful writing and local audio work. Do not say an image was generated, a soundtrack rendered or a chapter completed unless actual saved assets/scenes establish it.

`prepare_media` also automatically creates original project-owned title/logo art, a transparent pointer, and a dialogue-frame skin for our independent browser player. The creator does not have to request these separately. Gameplay uses our own React/Web API implementation; do not compile recovered commercial common scripts or launch an original game executable. Existing character portraits are reference inputs for the title. Check `status.uiSkin` as well as ordinary media. Repeat bounded calls with the returned revision until all executable roles are ready. For a requested visual revision use `vn_skin prepare` with a brief and only the explicitly requested `replaceRoles`; preserve previous assets. `vn_project preview` returns a browser project link/descriptor, not proof that a separate native window was opened.

Finish with `vn_director status`. Resolve missing scene targets/assets, insufficient saved beats, continuity discrepancies and abrupt planned relationship changes. These checks report concrete evidence and review prompts, not objective literary scores. Inspect the actual preview when available. A saved chapter with required art still pending, blocked or unassigned is a draft. Do not claim the whole request is complete or call `update_goal` with completion while required media or other production work remains; `status.ready` must be true and the saved result must satisfy the user's request. Report saved writing, actual media and any remaining blocker candidly, preserving the unfinished requirements for continuation.
