# VN Studio

VN Studio is a local AI-assisted visual novel authoring tool. Its React/Web API stage previews authored project JSON and admitted project media. Final game execution uses recovered common systems when recoveredSystemDirectory and recoveredCompilerExecutable are configured together. That path compiles recovered common scripts with authored story/media and launches the configured local engine; it retains the common title/menu, settings, storage and interaction code while applying project-owned title, pointer and dialogue skins. Without this local configuration the browser stage remains available.

The editor supplies a browser preview, choices and editing controls. In configured recovered mode, Run game launches the actual compiled game and Export game creates a standalone Windows ZIP, then opens its location. Browser restart remains an authoring preview action. Dirty/busy guards protect saved-project execution/export. Native and browser progress remain separate from authored projects; restart does not discard unsaved story edits. Generated title/dialogue/cursor images skin both presentation paths.

Configure projectDirectory; previewDirectory selects the build/export location. Use dev-tools/enable-vn-recovered-systems.mjs with an existing managed profile and validated local Korean/Japanese templates to activate recovered execution. The paired recovered paths are required together. dev-tools/use-browser-player.mjs is an explicit browser-only opt-out and removes those bindings; it must not run when recovered execution is intended. Preview receipts distinguish playback:recovered with directory/processId from playback:browser with a URL. Export packages only the runtime, a renamed Game.exe, launcher and empty local save directory; it excludes linked user saves, authoring/history and build metadata. Recovered templates/executables/resources remain private local inputs and are not shipped in the service repository.

## Model Experience

The default-on vn-director plugin and packaged skill plan cast, relationships, scene pacing and real media tasks, then write complete scenes. It prefers signed-in native Codex images and composes actual local WAV music/effects. prepare_media also prepares original title/logo, transparent cursor and dialogue-frame artwork in every playback configuration. Readiness checks actual admitted files, placements, scene reachability and production pacing. Existing assets, dialogue, choices and visual staging are preserved. Required unfinished media keeps production incomplete.

ChatGPT writing uses the existing account/Responses integration; image generation uses the public installed Codex app-server with managed sign-in. The app does not extract or publish credentials. An optional Images API key remains separate. Commands use current revisions, bounded jobs and cancellation. Agent mutation receipts are compact; explicit reads and UI methods return full authoring data.

## Direction and final game systems

The default director now plans emotional turns, referenced expression/pose variants, event CGs, and choices with immediate and later feedback. It applies automatically to new chapters and requested revisions. Existing chapters are preserved until requested for revision. Detailed authoring examples ship in `assets/skills/vn-director/references/direction.md` beside the default skill.

Each `lines[].visual` is a complete visual snapshot retained until the next cue; absent snapshots inherit the previous cue or scene visual. Supported direction fields are `shot` (`wide`, `medium`, `close`), `focus` (current portrait slot), `transition` (`cut`, `dissolve`) and `cg` (admitted background image id, replacing ordinary background/portraits). Include intended persistent music in each new full snapshot. The browser preview respects reduced motion. The recovered compiler emits corresponding composed images, native wipes and cue audio; its build metadata records cue/flag bindings. No Live2D or arbitrary animation timeline is implied.

Choices support bounded boolean `when` and `effects` maps. All conditions must match; unset flags read false. Effects survive manual and quick saves, clear on a new start, and never mutate authored stories. Native flags use dedicated named shared properties; only the new-game entry resets them, while native loads retain them. Existing documents and save slots without these additions remain readable. This is boolean story memory, not a numeric relationship simulation or history rollback.

Image tasks accept up to three admitted `referenceAssetIds`. Generate base portraits first, then use their returned ids to generate variants or event CGs through native Codex. References are integrity-checked project images and forwarded as native local-image inputs. The optional generations-only Images API adapter explicitly rejects reference editing requests rather than discarding them. Assign variants in beat snapshots; readiness recognizes both scene and beat image placements.

## Limits and licensing

Browser preview is the Windows/macOS-independent path and does not itself execute recovered systems. Actual Mac execution is untested. The configured recovered engine/export currently targets Windows and requires the user's validated local recovered templates. Each scene supports up to three visible portraits. Supplied game stories and all previously generated project assets remain user's data. Existing open-source dependencies retain their licenses; independent gameplay does not make the entire upstream application proprietary or wholly original. Historical recovered-runtime research does not grant commercial distribution rights to original commercial scripts, executable files or media.
