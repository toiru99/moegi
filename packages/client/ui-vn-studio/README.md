# Novel studio

VN Studio provides a guided visual novel workspace, revisioned projects, a default production director and native Siglus previews. The main surface shows the stage, production plan, dialogue, character placement and artwork/audio library beside the existing assistant. Project save/undo/run actions live in the editor footer. The assistant panel shows the current project/scene, actual scene/dialogue/media totals and the project-generated title artwork, with navigation back to planning or scene editing. It wraps the existing conversation without recreating its messages or composer. In recovered mode the browser shows scene composition; the actual original engine provides title, choices, save/load, history, auto/skip, audio and settings in its native window. This is a local development package.

The product uses VN Studio marks through the sidebar and conversation brand slots. Settings includes a separate ChatGPT connection section, using the same OAuth state and credentials as the editor. Legacy account, model, search and feedback integrations are disabled in the local profile. Upstream license notices remain with their sources.

Configure `projectDirectory`, `previewDirectory`, `compilerDirectory` and `fontFile` on the `vn-studio` row, then enable it. The bundle starts disabled so installation cannot silently select local directories or execute a player. `compilerDirectory` must contain the built Windows `siglus_script_compiler.exe`, `siglus_scene_linker.exe` and `siglus_engine.exe`. Preview selects the supplied font using its filename stem and copies it into the snapshot. The local development setup uses the full Noto Sans CJK KR Regular font; the subset Noto Sans KR and Malgun Gothic omit some Japanese kanji. Font source and license: [Noto Sans CJK](https://github.com/notofonts/noto-cjk/blob/main/Sans/README.md), [OFL](https://github.com/notofonts/noto-cjk/blob/main/Sans/LICENSE).

For the privately owned original game, set both `recoveredSystemDirectory` (a root containing `ko/manifest.json` and `ja/manifest.json`) and `recoveredCompilerExecutable` (the compatible siglus-ssu executable). `dev-tools/enable-vn-recovered-systems.mjs` safely applies this pair to the managed local profile. Preview verifies template file hashes, copies only the listed inputs, replaces exactly three original title story targets, compiles newly authored story scenes, and runs the original engine. A configured recovered build never silently falls back. Korean/Japanese common scripts, engine and resources remain outside the published package and original installation.

The home screen starts with empty title and story-idea fields. Create a project with the connected assistant, start an empty project for manual editing, or explicitly open saved work. A `project` URL opens that project; a remembered browser selection does not automatically reopen it. There is no bundled sample story or artwork. Existing projects and their assets remain readable. Import PNG/JPEG/WebP art and PCM/float WAV or Ogg/Vorbis audio; MP3 and Ogg/Opus are not admitted by this native preview pipeline. Images are normalized and bounded to 4096 pixels per dimension and a maximum 4:1 aspect ratio. Imported originals remain untouched. Assets live in each project's adjacent immutable content pool.

The editor saves, reloads, undoes saved changes and opens a compiled snapshot in Siglus. Clean projects automatically adopt agent saves; dirty projects retain the local draft and show a newer-version notice. Unsaved edits disable operations that would replace the draft. Save and undo require the loaded revision; choices must target an existing scene. The Host serializes writes within one running instance and retains up to five previous saved states within a 2 MiB document budget. Use one Host per authoring directory.

Artwork defaults to the installed, signed-in Codex CLI through its public stdio app-server protocol. `codexImageEnabled` defaults to true, `codexExecutable` to `codex`, and `codexImageTimeoutMs` to 300000. Readiness checks the CLI account and image capability without exposing credentials. The provider owns one process, isolated ephemeral read-only image jobs, cancellation and disposal; only completed native PNG files are admitted, and character files require actual transparency. This uses the signed-in Codex plan. The optional OpenAI Images API key connection remains separate and uses its API allowance. `maxAssetBytes` defaults to 8 MiB, `imageTimeoutMs` to 120000, and `imageModel` can be configured for that optional provider. All images pass through the same bounded asset intake as imports.

## Model Experience

The installed bundle includes the default-on `vn-director` component and a real discoverable packaged skill. It automatically contributes planning/writing/media instructions through the prompt registry, so creators need not name a skill or request each picture separately. Its `vn_director` tool saves a bounded production bible, writes scenes while preserving unrelated fields, prepares actual media and reports evidence-based progress. Defaults are five scenes and twelve to twenty saved dialogue/narration beats each; explicit user pacing overrides them. Readiness checks include actual file availability, scene reachability, incoming-branch relationship continuity, and media placement. These are review prompts rather than objective literary scores.

`vn_project` edits revisioned story data and `vn_media` handles imports, providers, image generation, score composition and effects. Exact importer results let repeated media tasks reuse the correct content-derived asset without name guessing. Director mutation tools return compact receipts with current revisions, changed IDs and counts; explicit reads and Remote UI methods retain full project data. Plan scores accept a structured object or JSON string and persist a validated string. Ready `codex-images` takes priority, so missing API credentials do not block native generation. Required media that remains unavailable or unassigned keeps production incomplete.

In recovered mode `vn_director prepare_media` automatically prepares project-owned title/logo artwork, a transparent mouse pointer and dialogue frame with native Codex, using existing planned character portraits as title references. `vn_skin` can also inspect or prepare those roles with an optional visual brief and explicit `replaceRoles`. The additive optional `uiSkin` document field stores image references; old project documents and undo history remain valid. Existing assigned roles and previous immutable assets are preserved. The adapter retains original TYPE2 cut geometry/centres and button atlases, hides original title logo/character layers, fits the pointer to 32×32 and crops the dialogue frame to the original lower 292-pixel slot. Build receipts record the five affected texture hashes and bindings; common behaviour is unchanged. Production readiness includes all three roles.

Legacy browser rehearsal stores slots and preferences in the adjacent `<id>.playback.json`, independently of production revisions. Quicksave uses slot zero; manual slots are one through six. Game loads verify the rendered and durable story fingerprints. Story replacement resets rehearsal history/timers; dirty production drafts disable game saves/loads. Gameplay never calls the authoring save operation. Native saves use the recovered SAVEPOINT/SYSCOM system and separate `savedata` storage scoped to the exact runtime, bytecode, configuration, font and media fingerprint; identical builds share saves, edited builds retain their own groups.

Writing sign-in and Responses transport remain owned by the existing `llm-pi-ai` provider; configure its `openai-codex` route and use Sign in with ChatGPT in the editor or Settings. Native images use the installed CLI's own managed Codex sign-in; the app does not extract or share its tokens. Guided story/music requests use the existing conversation. Music generation asks the model for a bounded score, then synthesizes actual WAV audio locally; this is a simple instrumental synthesizer. Sound presets require no model or API key. Both image providers forward cancellation through generation and the final queued project save. Optional API credentials remain in the existing Host credential store.

## Known Limitations and Deferred Work

This authoring subset supports static background/character composition, text, up to five original-system choices per scene and scene audio. It does not import complete commercial scripts or expose all Siglus commands. Characters are currently precomposed into per-scene backgrounds, so per-line sprite movement/expression animation remains future work. Choice appearance comes from recovered original resources; a scene with one authored transition still has only one choice. Cast-specific names/icons in the original voice-settings tab have not yet been replaced. Native engine common UI language follows the selected Korean/Japanese template. Legacy profiles without recovered configuration keep the earlier Rust prototype and separate browser rehearsal saves. Private original-engine resources are for this user's local template; the plugin publication contains no original game's runtime or commercial art. Windows native playback does not provide cross-platform export. Native image generation requires an installed signed-in Codex CLI with the imagegen skill and image capability enabled; its usage limits apply. Optional Images API generation requires a working API connection. Protocol tests alone are not proof of a live generation call.
